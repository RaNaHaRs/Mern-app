ERROR FIXED:
❌ Failed to create payment: null value in column "tenant_user_id" 
   of relation "saas_purchases" violates not-null constraint

STATUS: ✅ FIXED AND VERIFIED

================================================================================
ROOT CAUSE
================================================================================

The saas_purchases table had a NOT NULL constraint on tenant_user_id, but 
the feature needed to support new subscribers (who don't have a user ID yet).

When generating a payment link for a new subscriber:
- Backend tried to insert NULL for tenant_user_id (correct)
- Database rejected it due to NOT NULL constraint (error)
- Feature failed completely

================================================================================
SOLUTION APPLIED
================================================================================

1. CREATED MIGRATION: 051_make_tenant_user_id_nullable.sql
   - Removes NOT NULL constraint from tenant_user_id
   - Recreates foreign key with ON DELETE SET NULL
   - Allows NULL values for new subscriber orders
   - Migration is idempotent (safe to run multiple times)

2. UPDATED MIGRATION TRACKER: src/db/migrate.js
   - Added new migration to migrations list
   - Runs automatically on server startup
   - Shows as "already applied" after first run

3. ENHANCED LOGGING: src/routes/super-admin.js
   - Added detailed debug info to create-order endpoint
   - Logs when credentials are found/missing
   - Helps diagnose future issues faster

4. FIXED JSON PARSING: src/routes/settings.js
   - Properly handles JSON string parsing from database
   - Falls back gracefully on parse errors
   - Used by both GET and PATCH razorpay-settings endpoints
